# typomend-scorer

typomend-scorer 是 Typomend 的遮罩語言模型修正引擎：給它一段剛輸入的文字，它找出哪個字可能是選錯的同音字、應該換成哪個字，並給出信心比值。模型只當裁判，不負責找候選字，所以每個修正一定是輸入法可能打出的錯字。

## 它怎麼運作？

| 步驟 | 元件 | 做什麼 |
|------|------|--------|
| 1. 產生候選 | `Homophones` | 依讀音列出與輸入字同音的常用字（忽略聲調，ㄓㄔㄕ/ㄗㄘㄙ、ㄣ/ㄥ、ㄢ/ㄤ 視為相同），只取與文字相同字體（繁或簡）的字 |
| 2. 打分 | `CandidateScorer` | 用 BERT 類的遮罩語言模型（masked language model）算出每個候選字在上下文中的機率 |
| 3. 判斷 | `Detector` | 算出「最佳候選字 ÷ 輸入字」的機率比值 |
| 4. 修正 | `LmCorrector` | 檢查最近 8 個字，比值超過門檻才修正，一次只改一個字 |

以「我今天去打籃求」為例，macbert4csc 認為「球」比「求」可能約 30 萬倍，所以把「求」改成「球」。

### 最後幾個字怎麼處理？

模型要看前後文才判斷得準。錯字後面還沒有字時，最好的模型也只修正約一半的錯字，誤改也變多。所以最後 2 個字也會檢查，但門檻提高為 10 倍；後面多打了字或打了標點，就改用正常門檻。

在模擬輸入中比較幾種做法（繁中測試集，平衡模式）：

| 最後 2 個字的門檻 | macbert4csc | Google BERT |
|-------------------|-------------|-------------|
| 不檢查 | 31% / 1% | 32% / 0% |
| 正常門檻 | 74% / 8% | 71% / 10% |
| **10 倍（採用）** | 74% / 3% | 68% / 1% |
| 30 倍 | 71% / 2% | 62% / 0% |

每格是「修正率 / 誤改率」。不檢查最後幾個字時，一停下來就不會修正，只能修好約三成的錯字。

最後 2 個字沒達到 10 倍門檻、但達到正常門檻時，會再看一次：在文字後面補一個「。」重新打分，比值達到正常門檻的 100 倍就修正。例如「今天要去吃臭豆府」，「腐」只比「府」可能約 9,000 倍，補上「。」後變成約 500 萬倍。

在模擬輸入中比較（精準模式）：

| 模型 | 測試集 | 只看 10 倍門檻 | 加上補「。」再看一次 |
|------|--------|----------------|----------------------|
| macbert4csc | 繁體中文 | 83% / 0% | 84% / 0% |
| macbert4csc | 中英混打 | 70% / 2% | 72% / 2% |
| Google BERT | 繁體中文 | 73% / 0% | 83% / 0% |
| Google BERT | 中英混打 | 70% / 5% | 88% / 5% |

快速模式不做這一步。它的比值來自沒有遮罩的文字、門檻也低得多，再看一次會在 40 組中英混打的正確句中誤改 2 組。所有字都補「。」打分也不可行：誤改率從 0% 升到 4%，因為大部分時候使用者還會繼續打字。

### 三種模式差在哪？

| 模式 | 做法 | 每次檢查 |
|------|------|---------:|
| 精準 | 每個位置輪流換成 `[MASK]` 再打分 | 約 53 ms |
| 平衡 | 先不遮罩跑一次，可疑位置再用精準模式確認 | 約 35 ms |
| 快速 | 整句不遮罩只跑一次 | 約 25 ms |

延遲是在 CPU（f32）上模擬輸入測試句時，每次檢查的平均值。

## 各模型在不同語言的表現

每組測試都是「含一個錯字的句子」與「正確句子」成對：

| 測試集 | 內容 | 組數 |
|--------|------|-----:|
| `bench/zh-TW.tsv` | 繁體中文，臺灣日常用語 | 100 |
| `bench/zh-CN.tsv` | 簡體中文，中國大陸用語 | 99 |
| `bench/zh-TW-mixed.tsv` | 繁體中文夾雜英文與數字，例如「明天的demo準被好了嗎」 | 40 |

評測方式是**模擬實際輸入**：每句每次輸入 2 個字，每輸入一次就呼叫修正器並套用修正，跟 Typomend 實際運作相同。

- **修正率**：錯字句最後變成正確句的比例。
- **誤改率**：正確句最後被改動的比例。

各模型使用 `src/models.rs` 的建議門檻：在繁中測試集上，誤改率約 1% 以下時的最低門檻。

### BERT 類模型

| 模型 | 授權 | 模式（門檻） | 繁體中文 | 簡體中文 | 中英混打 |
|------|------|--------------|---------:|---------:|---------:|
| **macbert4csc**（轉簡體打分） | Apache-2.0 | 精準（3000） | **81% / 0%** | **83% / 0%** | 70% / 2% |
| | | 平衡（3000） | 73% / 0% | 74% / 0% | 65% / 0% |
| | | 快速（30） | 61% / 1% | 65% / 1% | 50% / 0% |
| Google BERT | Apache-2.0 | 精準（30） | 71% / 1% | 71% / 0% | 70% / 5% |
| | | 平衡（2） | 68% / 1% | 64% / 1% | 72% / 5% |
| | | 快速（2） | 57% / 0% | 59% / 0% | 62% / 0% |
| CKIP BERT base | GPL-3.0 | 精準（100） | 80% / 0% | 21% / **58%** | **82% / 0%** |
| CKIP BERT tiny | GPL-3.0 | 精準（300） | 45% / 1% | 7% / **86%** | 42% / 2% |

每格是「修正率 / 誤改率」。完整模型名稱與下載來源見 `src/models.rs`。

### 各語言該選哪個？

| 語言 | 建議 | 說明 |
|------|------|------|
| 繁體中文 | macbert4csc，精準模式 | 修正率最高且沒有誤改 |
| 簡體中文 | macbert4csc，精準模式 | 修正率最高（83%）且沒有誤改 |
| 中英混打 | macbert4csc 或 CKIP BERT base | CKIP 最好（82% / 0%），但只適合繁體 |
| 英文 | 不支援 | 這些模型與候選字表都以中文字為單位，英文拼字錯誤需要另一套以單字為單位的方法 |

**CKIP 只適合繁體中文。** 它只用繁體語料訓練，遇到簡體文字會把超過一半的正確句改錯。

**這些數字來自人工撰寫的小型測試集，混打測試集只有 40 組（1 組等於 2.5%）。** 加入更多真實錯字後，應重新評測。

## 如何評測自己的模型？

### 在 Typomend 裡評測

1. 開啟設定視窗的「遮罩語言模型」分頁，選擇已下載的模型和模式。
2. 按「準確度評測…」，在開啟的視窗按「開始評測」。

Typomend 會用目前的設定，對三個內建測試集模擬輸入，結果顯示在評測視窗，也會取代「遮罩語言模型」分頁的預期效果：每種語言的修正率、誤改率和每次檢查的時間。在 16 核心的電腦上，精準模式約需 25 秒，按「停止評測」可以中斷。

評測這樣維持在幾十秒內：

- **同時輸入多個句子**，用上所有處理器核心。每個執行緒自己做完模型運算，不把單一矩陣乘法分給所有核心，避免執行緒互相搶處理器。
- **共用兩句相同的部分。** 每組的錯字句與正確句在錯字之前完全一樣，同一段文字只問一次修正器，結果不變。
- **每次檢查的時間只用 6 組逐句輸入的句子量測**，所以不受同時輸入影響。改用 12 組量測，平均時間也只差幾毫秒。

### 用命令列評測

前置條件：Rust，以及放在 `models/<id>` 的模型。用下面的指令下載，`<id>` 是 `src/models.rs` 裡的模型名稱：

```powershell
cargo run --release -p typomend-scorer --example download -- <id> models/<id>
```

1. 模擬輸入，使用建議門檻：

   ```powershell
   cargo run --release -p typomend-scorer --example bench -- --typing --models macbert4csc-base-chinese --scripts s --modes m --sets zh-TW,zh-CN,zh-TW-mixed
   ```

2. 掃描門檻，找出某個模型的最佳門檻：

   ```powershell
   cargo run --release -p typomend-scorer --example bench -- --models google-bert-base-chinese --scripts t --sets zh-TW
   ```

模擬輸入預設同時輸入的句子數等於邏輯處理器數，用 `--jobs <N>` 可以改變。

用 `--set <檔案>` 可以評測自己的測試集：每行是「錯字句」、Tab、「正確句」，兩句只差一個字。
