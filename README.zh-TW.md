[English](README.md) | **繁體中文**

Typomend 是接在輸入法後面的自動修正層。它發現輸入法剛送出的同音錯字，就在原處改正；任何程式都適用，全部在你自己的電腦上完成。

你繼續用 Microsoft 注音，或原本習慣的任何輸入法。不用學新的輸入法、不用多按任何鍵，也不會把文字送到雲端：你打出「我今天去打籃求」，下一刻它就變成「我今天去打籃球」。

> **目前狀態：**早期的 side project。以繁體中文為主，簡體中文也能用，遮罩語言模型可以選擇不開。

## 為什麼需要 Typomend？

每一套中文輸入法都會選錯同音字：「再」打成「在」、「得」打成「的」、「應該」打成「因該」。常見的解法都要你改變習慣：

| 做法 | 你要付出的代價 |
|------|----------------|
| 換一套更聰明的輸入法 | 重新適應、重建詞庫，公司電腦還不一定准你安裝 |
| 打完再校對 | 複製、貼到檢查工具、看建議、再貼回去 |
| 送出前按一個鍵檢查 | 每次都要記得按，文字也常常要送到雲端 API |
| **Typomend** | **什麼都不用做。照常打字，回頭看時錯字已經不見了** |

Typomend 處理的是輸入法送出之後的文字，所以不管文字是哪一套輸入法打出來的，輸入法也繼續做它擅長的事。

## 特色

- **保留你的輸入法。** Typomend 完全不跟輸入法溝通。它透過 UI Automation（螢幕閱讀器使用的協助工具 API）讀取目前的文字欄位，修正已經送出的文字。
- **全自動。** 沒有快速鍵，也沒有要你確認的視窗。**組字中的文字一律不動。**
- **在本機執行，以隱私為前提設計。** 規則和遮罩語言模型都在本機執行。記錄檔不會記下你打的內容，開啟不記錄模式後連記錄檔和修正紀錄都不保留。
- **兩層修正引擎。** 規則清單處理你已知的錯字，可選的本機遮罩語言模型處理你沒想到的錯字。遮罩語言模型會根據上下文，填回被遮住的字，所以 Typomend 請它評估每個同音字的可能性；它只負責打分數，不會產生文字。預設模型在模擬輸入中修好 81% 的繁體中文同音錯字，正確的句子一句都沒改到。
- **用數據說話。** **遮罩語言模型** 分頁可以在你自己的電腦上評測模型，顯示修正率、誤改率和每次檢查的時間。
- **你在哪裡打字，就在哪裡修正，終端機也一樣。** 瀏覽器、記事本、檔案總管、VS Code、Windows Terminal、PowerShell，以及在裡面執行的 Claude Code 這類 AI 程式助理。每個程式都能設定自己的修正模式。
- **不需要系統管理員權限。** 單一執行檔，以你的帳號執行，開機啟動也只寫入你自己的設定。

## 快速對照

| 想做的事 | 做法 |
|----------|------|
| 執行 | 從[最新版本](../../releases/latest)下載 `typomend-<版本>-x86_64-pc-windows-msvc.zip`，解壓縮後啟動 `typomend.exe` |
| 開啟設定 | 左鍵點系統匣圖示 |
| 暫停修正 | 右鍵點系統匣圖示，選 **暫停修正** |
| 開機時啟動 | 系統匣選單或 **設定** 分頁，勾選 **開機時啟動** |
| 修正規則沒列到的錯字 | **規則** 分頁選擇 **規則清單＋遮罩語言模型**，再到 **遮罩語言模型** 分頁下載模型 |
| 加入自己的修正 | **規則** 分頁按 **編輯規則**，改完存檔 |
| 看模型在我的電腦上表現如何 | **遮罩語言模型** 分頁按 **準確度評測…** |
| 某個程式不要修正 | **應用程式** 分頁選取該程式，把 **修正模式** 設為 **關閉** |
| 結束 | 系統匣選單選 **結束**。關閉視窗只會把它藏起來 |

## 怎麼運作？

Typomend 透過 [UI Automation](https://learn.microsoft.com/windows/win32/winauto/entry-uiauto-win32) 觀察目前選取的文字欄位：

1. UIA TextEdit 事件會回報組字過程的每一個按鍵，所以 Typomend 知道你還在組字，組字中的文字一律不動。
2. 組字確認送出、鍵盤短暫閒置之後，Typomend 檢查游標前面的文字。
3. 選取錯字並替換，再讀回內容確認修正成功。

Typomend 只讀取游標前的一小段文字，並透過 UI Automation 事件得知內容有變動，所以長文件和短文件的負擔一樣。瀏覽器的文字欄位越長，回應 UI Automation 就越慢；回應慢到無法安全修改的欄位（在 Chrome 或 Edge 大約是 30 萬字）會被略過。修正寫入之前你又開始打字的話，這次修正也會取消。

處理方式取決於欄位提供了什麼，而不是它屬於哪個程式：

| 欄位類型 | 例子 | 替換方式 | 能否驗證 |
|----------|------|----------|----------|
| 讀得到內文 | 記事本、Chrome、Edge、檔案總管搜尋框 | 透過 UIA 選取，再用 `EM_REPLACESEL` 或模擬打字 | 可以 |
| 讀不到內文，但會回報組字 | 關閉協助工具支援的 VS Code | 從游標位置用方向鍵移過去改（盲改模式） | 不行 |
| 命令列 | Windows Terminal、傳統主控台，以及在裡面執行的 shell 或程式 | 從游標位置用方向鍵和 Backspace 逐步修改（終端機模式） | 可以 |
| 密碼欄位、以系統管理員身分執行的程式 | | 不處理 | |

## 修正引擎

在 **規則** 分頁選擇引擎：

| 引擎 | 能修正 | 代價 |
|------|--------|------|
| 規則清單 | `rules.txt` 裡列出的錯字 | 幾乎感覺不到，20 萬條規則也一樣 |
| 規則清單＋遮罩語言模型 | 列出的錯字，加上規則沒列到的同音錯字，例如「因問」改成「因為」、「打籃求」改成「打籃球」 | 下載數百 MB 的模型，在 CPU 上每次檢查數十毫秒 |

### 遮罩語言模型怎麼判斷？

模型只當裁判，不負責改寫。Typomend 對最近打的每個字列出同音字，請 BERT 模型評估每個同音字放在上下文裡的可能性，只有某個同音字比原本的字可能好幾倍時才替換。**所以每個修正都是你打的字的同音字或近音字，不會改寫句子**，而且一次只改一個字。候選字會維持原文的字體，「為」不會被改成「为」。

模型要看到錯字後面的文字才判斷得準，所以最後兩個字在後面還沒有文字之前，會用高 10 倍的門檻檢查。

預設模型 macbert4csc 在精準模式下，以每次 2 個字模擬輸入內建測試集的結果：

| 測試集 | 修正率 | 誤改率 |
|--------|-------:|-------:|
| 繁體中文 | 81% | 0% |
| 簡體中文 | 83% | 0% |
| 中英混打 | 70% | 2% |

**遮罩語言模型** 分頁還提供其他 BERT 模型，以及每次檢查約 25 到 53 毫秒的三種模式。各模型、模式和測試集的完整比較見 [`crates/typomend-scorer/README.md`](crates/typomend-scorer/README.md)。

## 每個程式的修正模式

**應用程式** 分頁會列出你輸入過文字的程式。選取一個程式，就能決定它的修正方式：

| 模式 | 做法 |
|------|------|
| 自動 | 預設值，依欄位提供的資訊選擇做法，如上表；終端機使用終端機模式 |
| 標準 | 只修正讀得到內文的欄位：選取錯字、取代，再讀回確認。終端機會被略過 |
| 盲改 | 從游標位置用方向鍵修正，不讀取內文；即使讀得到內文也一樣 |
| 終端機 | 用於命令列：讀取游標前的文字，用方向鍵和 Backspace 修正後再讀回確認。也可以套用在只適合這種做法的其他程式 |
| 關閉 | 不修正這個程式 |

在終端機裡選取文字只會進入標記模式，不會移動 shell 的游標，所以終端機改用按鍵修正。只要是用方向鍵和 Backspace 編輯的地方都適用：Windows Terminal 和傳統主控台裡的 PowerShell、cmd、Claude Code。每一步都會先讀回確認才送出下一步，刪除之前也會先確認游標位置，所以遇到方向鍵另有用途的程式，修正會直接停止，不會動到文字。不論選哪個模式，密碼欄位和以系統管理員身分執行的程式一律略過。

## 規則

第一次執行時會建立 `rules.txt`，裡面有內建的 273 條常見錯字。規則存在一個 UTF-8 純文字檔裡，可以用記事本、VS Code 或任何編輯器修改，也可以一次貼上幾千條。**存檔的瞬間 Typomend 就會套用**，不需要重新啟動。

```text
# 以 # 開頭的行會被忽略；把規則註解掉就等於停用它。
因該 = 應該
在見 = 再見
```

- 一行一條，格式是 `錯字 = 修正文字`，`=` 前後的空白會被忽略。
- 同一個錯字出現兩次時，以後面那行為準。
- 讀不懂的行會被略過，**規則** 分頁會顯示第一個有問題的行號。

所有規則會編譯成一個 [Aho-Corasick](https://zh.wikipedia.org/wiki/AC%E8%87%AA%E5%8A%A8%E6%9C%BA%E7%AE%97%E6%B3%95) 自動機，不管清單多長，查詢時間都一樣。20 萬條規則時，存檔後約 0.25 秒就會生效。

規則檔是純文字，所以團隊可以共用一份產品名稱、人名和專有名詞的清單，讓每個人的電腦都用同樣的方式修正。

## 下載

從[最新版本](../../releases/latest)下載 `typomend-<版本>-x86_64-pc-windows-msvc.zip`，解壓縮到會長期保留的資料夾，再執行 `typomend.exe`。**開機時啟動** 會從這個資料夾啟動它。檔名結尾是這個版本適用的平台：`x86_64-pc-windows-msvc` 代表 Intel 或 AMD 處理器的 64 位元 Windows。壓縮檔裡也附上授權條款和這份說明。

每個版本也會附上壓縮檔的 SHA-256 檢查碼，檔名是壓縮檔名稱後面加上 `.sha256`，可以用來驗證下載的檔案。

加上 `--background` 參數會直接縮在系統匣啟動，**開機時啟動** 就是用這個方式。

## 設定與隱私

| 項目 | 位置 |
|------|------|
| 設定檔 | `%APPDATA%\typomend\config.toml` |
| 規則檔 | `%APPDATA%\typomend\rules.txt` |
| 遮罩語言模型 | `D:\Typomend\models`；沒有 D 槽時是 `C:\Typomend\models`，也可以自選資料夾 |
| 記錄檔 | `%LOCALAPPDATA%\typomend\logs` |
| 修正紀錄 | 只存在記憶體，結束 Typomend 就清除 |

**記錄檔不會記下你打的內容**，只記錄程式名稱、支援類型和修正結果。文字只在你的電腦上檢查；唯一的網路連線是你自己按下的模型下載。

從系統匣選單或 **設定** 分頁開啟 **不記錄模式**，就會停止寫入記錄檔，也不再保留修正紀錄；**設定** 分頁的 **刪除記錄檔** 可以清掉已經寫下的記錄檔。

## 專案結構

| 路徑 | 內容 |
|------|------|
| `crates/typomend` | 系統匣程式：視窗、設定、多語系 |
